# x86_64 GPU: NVIDIA driver, NVDEC, NVK and Zink

This is the X399 workstation's graphics stack: a GTX 1080 Ti (Pascal). It
also runs on a GTX 1070. The details are in Haiku's
`docs/x399-workstation/STATUS.md`. The stack has four parts. Each one now
comes from Git:

| Part | What it does | Source |
|---|---|---|
| `nvidia_rm`, `nvidia_rm_modeset` | kernel driver: X547's Haiku OS layer around NVIDIA's resource manager, plus NVKMS for display | haiku `src/add-ons/kernel/drivers/graphics/nvidia_rm` (from X547/nvidia-haiku, forked as jmgasper/nvidia-haiku `airos`); jmgasper/open-gpu-kernel-modules `airos-570.86.16-haiku` (X547's Haiku branch); the RM core `nv-kernel.o_binary` of NVIDIA's 570.86.16 Linux driver, downloaded from NVIDIA and checked against its SHA-256 |
| `nvidia_rm.accelerant` | app_server's side: modes, displays, the cursor, vertical sync | haiku `src/add-ons/accelerants/nvidia_rm` |
| `nvdec` media add-on | H.264 (and H.265 for programs that ask) decoded on the card's NVDEC engine | haiku `src/add-ons/media/plugins/nvdec`, with the RM API of jmgasper/mesa-nvk |
| NVK | Vulkan on the card | jmgasper/mesa-nvk `airos-nvk-r2`: X547/mesa `mesa-nvk-r2` (`b28d7c6`) plus haiku `docs/x399-workstation/patches/mesa-nvk/0001-0007` |
| Zink renderer add-on | Haiku's OpenGL kit (BGLView programs) on Vulkan | jmgasper/mesa `airos-22.0.5-hgl`: Mesa 22.0.5, HaikuPorts' Haiku patches, and haiku `docs/x399-workstation/patches/mesa-hgl/0001-0014` |

## In the x86_64 image now

`deps/build-nvidia.sh` cross-builds the driver, the accelerant and NVDEC
using the Haiku tree of the x86_64 SDK. The sdk-deps workflow runs it. The
image puts the results in `system/non-packaged/add-ons`, as the workstation
had them, so the boot menu's "Disable user add-ons" turns them off.

- The driver binds only to NVIDIA GPUs. It has been tested on Pascal; other
  generations that NVIDIA's 570 driver covers are untested on Haiku.
- NVDEC registers H.264 only when `/dev/nvidiactl` exists. Haiku uses one
  decoder per format, and an add-on that claimed H.264 everywhere would
  stop H.264 playing on every machine without an NVIDIA card.
- There is no NVIDIA-specific OpenGL or Vulkan yet. On the X399, OpenGL is
  Haiku's software renderer, and Summit uses its private Mesa's llvmpipe.

## Next: NVK and Zink

Both are forked, but not built by CI yet.

**NVK.** Mesa 25.3's NVK compiles shaders with NAK, which is written in Rust.
The workstation built it natively with HaikuPorts' Rust
(`docs/x399-workstation/tools/haiku-build-nvk.sh`). For CI there are two
routes:

1. **Cross-compile.** Install a Rust toolchain on the build server and build
   the standard library for `x86_64-unknown-haiku`, a tier 3 target with no
   prebuilt std (`cargo +nightly build -Zbuild-std`, linking with the Haiku
   cross GCC). Then point meson's cross file at it (`rust = ['rustc',
   '--target', 'x86_64-unknown-haiku', '--sysroot', ...]`). NAK's crates come
   from Mesa's meson wraps; proc-macros build for the host. NVK also needs
   SPIRV-Tools and the host `mesa_clc` that `deps/build-gl.sh` already
   builds.
2. **Native, in a Haiku VM on the build server.** Boot the CI's own x86_64
   image under KVM, install HaikuPorts' `rust_bin`, `llvm20`, `meson`,
   `spirv_tools` and the rest, and run `haiku-build-nvk.sh` there. This
   matches the tested build exactly, at the cost of maintaining a VM.

The output is `libvulkan_nouveau.so` and its ICD json, for
`system/non-packaged/add-ons/vulkan/icd.d`. HaikuPorts' `vulkan` loader is
already in the x86_64 image for Summit's zink.

**Zink renderer add-on.** It is Mesa 22.0.5 with C sources only, so it
cross-builds the way `deps/build-gl-x86_64.sh` builds Mesa 25.3: meson cross
file and HaikuPorts' `vulkan_devel`. The build options are
`docs/x399-workstation/tools/build-mesa-hgl.sh`'s. It should go into the
image together with NVK, because without a Vulkan device it has nothing to
draw with. With both installed:
- BGLView programs on the X399 run on the GPU;
- Summit's private Mesa picks zink over llvmpipe (on the workstation, its
  launcher sets the glvnd vendor).
